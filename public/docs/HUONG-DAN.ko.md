# KMart 시스템 사용 안내서

> 이 안내서는 **일반 사용자와 관리자**를 위한 문서입니다. 내용을 **역할별**로 나누어 두었으니
> 사원, 결재자, 인사, 관리자 중 본인에게 필요한 부분만 읽으면 됩니다.
> 모든 단계에 **메뉴 경로**를 적어 두었으니 그대로 따라 하면 됩니다.

![네 가지 역할과 각 역할이 하는 일](/docs/img/ko/so-do-vai-tro.svg)

## 0. 본인의 역할과 읽어야 할 부분
<!-- seen-by: all -->

시스템에는 **네 가지 역할 그룹**이 있습니다. 역할에 따라 보이는 메뉴와 할 수 있는 일이 달라집니다.

| 역할 (코드) | 시스템에서 하는 일 | 읽을 부분 |
|---|---|---|
| **사원** (STAFF) | 본인 요청서 작성, 진행 상황 확인, 서류 보완, 취소 | **1** → **2** → **6** |
| **결재자** (MANAGER · TEAM_LEADER · 그 밖의 결재 역할) | 본인에게 온 요청서 처리, 부재 시 위임, 대리 결재자 설정 | **1** → **3** → **6** |
| **인사** (HR) | 직원 관리, 비밀번호 재설정, 부서, 보고서 조회 | **1** → **4** → **6** |
| **관리자** (ADMIN) | 양식, 결재 흐름, 직위, 텔레그램, 기한 설정 | **1** → **5** → **6** |

**모든 역할 공통:** 로그인, 비밀번호 변경 필수, 알림 벨, 텔레그램 연결 (**1장**과 **6장**).

> 한 사람이 사원이면서 결재자일 수 있습니다. 그런 경우 **3장**도 함께 읽으세요. 하나의 계정으로
> 두 가지 업무를 모두 처리합니다.

> 이 페이지는 계정에 권한이 있는 부분만 보여줍니다. 사원에게는 인사·관리자 부분이 보이지 않고,
> 반대의 경우도 마찬가지입니다.

### 메뉴별 기능

| 메뉴 | 하는 일 | 볼 수 있는 사람 |
|---|---|---|
| **부서 & 그룹** | 조직도, 부서 정보와 구성원, 해당 부서의 요청서와 보고서 | 모든 사용자 |
| **인사** | 직원 목록, 계정 생성, 비밀번호 재설정, 시스템 역할 | 인사 / 관리자 |
| **요청서 → 내 요청서** | 요청서 작성, 본인 요청서 추적, 서류 보완 또는 취소 | 모든 사용자 |
| **요청서 → 내 결재 대기** | 본인 차례의 요청서 처리: 결재, 반려, 보완 요청, 댓글 | 결재 권한 보유자 |
| **보고서** | 개요 지표, 12개월 추세, 유형/부서별 분포, 엑셀 내보내기 | 인사 / 관리자 |
| **위임 → 임시 위임** | 부재 중 결재 권한을 다른 사람에게 넘김 | 결재 권한 보유자 |
| **위임 → 기한 초과 대리 결재** | 본인이 결재하는 요청서의 기본 대리 결재자 설정 | 결재 권한 보유자 |
| **설정 → 서식 양식** | 요청서 양식과 입력 항목 설계 | 관리자 / 인사 |
| **설정 → 결재 흐름** | 요청서 유형별 결재 흐름 구성 | 관리자 / 인사 |
| **설정 → 직위 & 직급** | 결재 기준으로 쓰는 직위 관리 | 관리자 / 인사 |
| **설정 → 일반 & 텔레그램** | 텔레그램 봇 설정, 기한 초과 시간 계산 방식 | 관리자 / 인사 |
| **계정** (사이드바에서 이름 클릭) | 본인 프로필, 텔레그램 연결/변경, 연락처 수정 | 모든 사용자 |
| **가이드** | 지금 읽고 있는 이 문서 | 모든 사용자 |

## 1. 공통: 로그인, 비밀번호 변경, 화면 이동
<!-- seen-by: all -->

### 1.1. 로그인

목적: 인사가 발급한 계정으로 시스템에 접속합니다.

![로그인과 비밀번호 변경 필수 4단계](/docs/img/ko/dang-nhap.svg)

1. KMart 웹 주소로 접속하면 로그인 화면에 **업무 이메일**과 **비밀번호** 두 칸이 나타납니다.
2. 회사 이메일 + 비밀번호를 입력하고 **로그인**을 누릅니다 (또는 **Enter**).
3. 정보가 틀리면 **입력란 바로 아래**에 오류가 표시됩니다. 고쳐서 다시 시도하면 되고 새로고침은 필요 없습니다.

**결과:** 역할에 맞는 메인 화면으로 들어갑니다.

### 1.2. 인사가 비밀번호를 재설정한 뒤 첫 로그인

인사가 방금 비밀번호를 재설정했다면 시스템이 **차단**하고 **비밀번호 변경 필수** 화면을 엽니다.

1. **현재 임시 비밀번호** — 인사가 알려준 임시 비밀번호 (텔레그램 발송 또는 직접 전달).
2. **새 비밀번호**와 **새 비밀번호 재입력** — 본인 비밀번호를 정합니다.
3. 새 비밀번호는 입력란 아래에 표시된 **5가지 조건**을 만족해야 합니다:
   최소 **8자**, **대문자**, **소문자**, **숫자**, **특수문자** 각 1자 이상.
4. **비밀번호 변경 후 계속**을 누릅니다. 잘못 입력하면 문제가 있는 칸을 정확히 알려줍니다
   (예: "비밀번호가 일치하지 않습니다").

> 이 화면은 건너뛸 수 없습니다. 임시 비밀번호로는 어떤 메뉴에도 들어갈 수 없습니다.

### 1.3. 로그인 후 화면 구성

![내비게이션: 사용자 정보, 알림 벨, 권한별 메뉴](/docs/img/ko/thanh-dieu-huong.svg)

- **왼쪽 아래** (PC 기준)에 **이름, 역할, "접속 중"** 상태가 표시됩니다. 이곳(또는 프로필 사진)을
  누르면 **계정** 페이지가 열립니다.
- 이름 옆에 **알림 벨**이 있습니다. **빨간 점**은 읽지 않은 시스템 알림 개수이며, 누르면 목록이 열립니다.
  **휴대폰**에서는 벨이 **오른쪽 상단**으로 이동합니다.
- **왼쪽 메뉴**는 권한이 있는 항목만 표시됩니다. 예를 들어 사원에게는 **인사**, **보고서**, **설정**이
  보이지 않고, 결재 권한이 있으면 **내 결재 대기**와 **위임**이 추가됩니다.
- 로그인 화면과 앱 안의 **VI / EN / KO** 버튼으로 인터페이스 언어를 바꿉니다.
- **좁은 화면 / 휴대폰**에서는 긴 블록(필터, 요청서 정보)이 자동으로 접힙니다. 제목 줄을 누르면 펼쳐집니다.

## 2. 역할: 사원 — 본인 요청서 작성과 추적
<!-- seen-by: all -->

### 2.1. 요청서 작성

목적: 요청(휴가, 초과근무, 구매, 출장 등)을 결재 흐름에 상신합니다.

![요청서 작성 3단계](/docs/img/ko/tao-don.svg)

**요청서 → 내 요청서**로 이동해 **새 요청서 작성**을 누르면 **새 요청서 작성** 창이 열립니다.

1. **요청서 유형** — 필요한 유형을 고릅니다. 고르면 해당 유형의 동적 양식이 나타나 입력할 항목을
   보여줍니다 (예: 휴가 신청서의 시작일 / 종료일 / 총 일수).
2. **수신 부서** — 본인이 여러 부서(주/겸직)에 속해 있으면 어느 부서로 보낼지 선택합니다.
3. **양식 작성** — `*` 표시된 항목을 모두 입력합니다. 날짜 항목은 달력에서 선택합니다.
4. **예상 결재 흐름** — 창 아래 블록에서 요청서가 누구를 거쳐 갈지 보여줍니다.
   **여기를 눌러 흐름 보기**를 누르면 기안자 → 각 결재 단계 → 완료까지 전체 도식이 열립니다.
5. **사유 / 설명** — 결재자가 판단할 수 있도록 사유를 분명히 적습니다.
6. **요청 상신**을 누릅니다.

**결과:** 요청서가 **대기** 상태가 되고, 1단계 결재자에게 즉시 알림이 갑니다 (시스템 알림, 텔레그램을
연결했다면 텔레그램도).

> 작성 창에는 **취소**와 **요청 상신** 두 버튼만 있습니다. 임시 저장 버튼은 없습니다. 요청서가
> **임시저장** 상태가 되는 경우는 파일 첨부가 실패했을 때뿐입니다 (2.4 참고).

#### 상신 전 확인 목록

- `*` 표시 항목을 모두 입력했고, 날짜가 의도한 기간과 맞는지.
- 결재 흐름 도식을 한 번 더 확인: 결재자와 단계 수가 맞는지.
- 유형이 허용한다면 증빙 파일을 첨부해 결재자가 다시 묻지 않도록 합니다.

### 2.2. 1단계에 후보가 여러 명일 때 결재자 선택

![1단계 후보가 여러 명일 때 결재자를 고르는 3단계](/docs/img/ko/chon-nguoi-duyet.svg)

- 결재 흐름 1단계에 **결재 가능한 사람이 여러 명**이면 시스템이 **결재자 선택**에서 한 명을 고르도록
  **강제**합니다. 요청서가 모든 후보에게 나뉘지는 **않습니다**.
- 흐름에 **이미 한 명만** 지정되어 있으면 그 이름이 표시되고 선택 상자는 나타나지 않습니다.
- 결재자가 잘못 지정되었다면 그것은 **결재 흐름 설정** 문제이지 본인 실수가 아닙니다. 관리자에게
  5.3장을 확인하도록 요청하세요.

### 2.3. 요청서와 결재 흐름 추적

![상태 탭, 요청서 카드, 요청서 상세 3단계](/docs/img/ko/theo-doi-don.svg)

1. **요청서 → 내 요청서**로 이동합니다. 상태 탭은 **전체**, **대기**, **보완 필요**, **승인 완료**,
   **반려**입니다. 검색창과 **부서** / **요청서 유형** 필터가 있습니다.
2. 카드에는 이미 요청서 유형, 요청서 번호, 색상 상태 배지, **현재 단계 / 전체 단계**, 결재 대기 중인
   사람이 표시됩니다. **결재 흐름 자세히 보기**를 누르면 **목록 안에서** 단계 도식이 열립니다
   (버튼이 **결재 흐름 숨기기**로 바뀝니다).
3. 카드를 누르면 **상세 화면**이 열립니다: 입력 내용, 첨부 파일, **댓글** 창(`@`로 이름 언급),
   그리고 각 단계의 **진행 상황**(누가 언제 결재했는지).
4. 요청서가 단계를 넘길 때마다 알림을 받습니다: 방금 결재한 사람과 다음 결재자.

### 2.4. 요청받은 서류 보완

![서류 보완 3단계와 요청서 취소 3단계](/docs/img/ko/sua-va-huy-don.svg)

1. 보완이 필요한 요청서는 목록에서 **보완 요청** 배지가 붙고 텔레그램 메시지도 옵니다(연결한 경우).
   **보완 필요** 탭에 모여 있습니다.
2. 요청서를 열고 **보완**을 누르면 **요청서 보완** 창이 열립니다. 결재자가 요청한 항목/파일을 채웁니다.
3. **보완 & 재상신**을 누릅니다.

**결과:** 요청서가 **진행 중이던 단계 그대로** **대기** 상태로 돌아갑니다(처음부터 다시 결재하지
않습니다). 해당 단계 결재자에게 알림이 갑니다.

> **첨부 파일 업로드 실패:** 시스템은 요청서를 **임시저장** 상태로 저장하고 어떻게 처리할지 물어봅니다:
> **남아서 수정** · **다시 업로드** · **파일 없이 전송**. 서류가 빠진 채 조용히 상신되는 일은 없습니다.

### 2.5. 요청서 취소

**아무도 결재하지 않았을 때만 취소할 수 있습니다.** **요청서 취소** 버튼은 요청서가 **대기** /
**보완 필요** / **임시저장** 상태이고 본인이 기안자일 때만 나타납니다. 누군가 한 단계라도 결재하면
버튼이 사라집니다.

1. 요청서를 열고 **요청서 취소**를 누릅니다.
2. **이 요청서를 취소할까요?** 창이 열립니다. **취소 사유**를 입력합니다 — **선택 사항**(최대 1000자)이지만
   결재자가 상황을 이해할 수 있도록 적는 것이 좋습니다.
3. **요청서 취소 확인**을 누릅니다 (**요청서 유지**를 누르면 취소하지 않습니다). **되돌릴 수 없습니다.**

**결과:** 요청서가 **취소됨** 상태가 됩니다. 결재 대기 중이던 사람에게도 알림이 갑니다.

### 2.6. 알림

![시스템 알림 벨과 텔레그램 두 채널](/docs/img/ko/thong-bao.svg)

- **웹 시스템:** 사이드바(PC) 또는 오른쪽 상단(휴대폰)의 벨. **빨간 점**은 읽지 않은 알림 수이며,
  한 줄을 누르면 해당 페이지가 열립니다.
- **텔레그램**(연결한 경우): 결재 차례, 기한 임박, 기한 초과 이관, 승인 / 반려 / 보완 요청, 취소 등
  요청서의 모든 이벤트가 **자세히 보기** 링크와 함께 옵니다. 인사가 재설정한 임시 비밀번호도 여기로 옵니다.

텔레그램 연결 방법은 **6장**을 보세요.

## 3. 역할: 결재자 — 본인 차례의 요청서 처리
<!-- seen-by: approver -->

### 3.1. 결재 대기 목록

![결재 대기 목록을 열고 요청서를 처리하는 3단계](/docs/img/ko/hang-cho-duyet.svg)

1. **요청서 → 내 결재 대기**로 이동합니다.
2. 본인 차례인 요청서와, 위임 기간 중 **본인에게 위임된** 요청서가 함께 표시됩니다.
3. 각 카드에는 양식, 기안자, 현재 단계, **남은 기한**이 표시됩니다.
4. 카드를 누르면 작성된 양식, 첨부 파일, 이력, 진행 상황이 열립니다.

**가장 빠른 방법:** 텔레그램 메시지의 **자세히 보기** 링크로 바로 요청서를 엽니다.

### 3.2. 요청서에 대한 세 가지 처리

![결재자의 세 가지 처리: 결재, 반려, 보완 요청](/docs/img/ko/thao-tac-duyet.svg)

| 처리 | 조건 | 결과 |
|---|---|---|
| **요청서 결재** | 추가로 적을 내용 없음 | 요청서가 **다음 단계**로 넘어갑니다. 마지막 단계면 **승인 완료**가 됩니다. 기안자와 다음 결재자에게 알림. |
| **반려** | **사유 입력 필수** — 비어 있으면 전송이 막힙니다 (최대 1000자) | 요청서가 **반려** 상태가 되고 기안자가 **사유**를 받습니다. |
| **보완 요청** | **무엇이 필요한지 반드시 명시** | 요청서가 **보완 요청** 상태로 기안자에게 돌아가며 **단계는 그대로 유지**됩니다. 재상신 후 다시 결재합니다. |

> 한 단계에는 이 **세 가지** 처리만 있습니다. "다른 결재자에게 전달"이나 "기안자 대신 내용 수정"은 없습니다.
>
> 반려 사유는 **항상 필수**이며 시스템에서 끌 수 없습니다.

### 3.3. 댓글과 이름 언급

![댓글 창에 @를 입력해 이름 언급](/docs/img/ko/binh-luan.svg)

- 상세 화면의 **댓글** 창에서 기안자와 다른 단계의 결재자와 소통합니다.
- `@`를 입력하면 사용자 목록이 열려 이름을 언급할 수 있고, 해당 사용자에게 **"새 댓글"** 알림이 갑니다.
- 댓글은 요청서 진행 항목에 표시되며 **모든 결재 단계에서 읽을 수 있습니다**.

**팁:** 바로 반려하지 말고 댓글로 확인하세요. 기안자가 보완할 수 있다면 훨씬 빠르게 진행됩니다.

### 3.4. 부재 중 임시 위임

목적: 장기간 자리를 비워도 요청서가 밀리지 않게 합니다.

![임시 위임을 만드는 3단계](/docs/img/ko/uy-quyen-tam-thoi.svg)

1. **위임 → 임시 위임**으로 이동해 **위임 생성**을 누릅니다.
2. **3가지 필수 정보**를 입력합니다: **수임자** · **시작일–종료일** · **위임 사유**.
3. 기간 중에는 본인에게 올 요청서를 **수임자**가 처리하며, 시스템에 **"누구를 대신해 결재하는지"**가
   표시됩니다.

언제든 **담당자 변경** 또는 **회수**로 조기 종료할 수 있습니다. 기간이 끝나면 권한은 자동으로
본인에게 돌아옵니다.

### 3.5. 기한 초과 대리 결재자 설정

목적: 본인이 기한을 넘겼을 때 요청서가 취소되지 않고 믿을 수 있는 사람에게 넘어가도록 합니다.

![기본 대리 결재자를 설정하는 3단계](/docs/img/ko/duyet-thay-qua-han.svg)

1. **위임 → 기한 초과 대리 결재**로 이동합니다.
2. **대리 결재자 설정**(이미 설정했다면 **담당자 변경**)을 누르고 상대를 고른 뒤
   **대리 결재자 저장**을 누릅니다.
3. 본인이 결재하는 요청서가 기한을 넘기고 해당 단계가 **"기한 초과 위임으로 결재"**로 설정되어 있으면,
   요청서가 그 사람에게 새 기한과 함께 넘어갑니다.

**알아 둘 점:**

- 한 사람당 대리 결재자는 **한 명**만 설정할 수 있고, 다시 저장하면 기존 설정이 **덮어써집니다**.
- 이 설정은 **본인이 결재하는 모든 요청서**에 적용되며 결재 단계별로 따로 설정하지 않습니다.
- **설정하지 않으면** 본인이 기한을 넘긴 요청서는 **취소**됩니다.
- 기한 초과 이관은 모두 **감사 로그**에 기록됩니다.

### 3.6. 요청서가 기한을 넘기면 무슨 일이 생기나

![결재 단계가 시간에 따라 어떻게 처리되는지](/docs/img/ko/qua-han.svg)

**기한 전:** 현재 결재자가 요청서 링크와 함께 **"결재 기한이 임박했습니다"** 알림을 받습니다.

> 알림은 **단계당 정확히 1회**만 발송되며 반복되지 않습니다. 스팸 방지를 위한 의도된 동작입니다.
> 요청서가 **새 단계**로 넘어가야 다시 알림이 옵니다.

**기한 초과 & 미처리:** 시스템이 해당 단계에 설정된 처리 방식에 따라 **자동 처리**합니다. **2가지**입니다.

1. **요청서를 기안자에게 반환** — 요청서가 기안자에게 돌아갑니다.
2. **기한 초과 위임으로 결재** — 해당 단계 결재자가 **기한 초과 대리 결재**에서 설정한
   **대리 결재자**에게 넘어갑니다 (3.5장).

**두 번째 기한 초과:** 대리 결재자도 기한을 넘기면 요청서는 **취소**되어 기안자에게 반환됩니다.
대리 결재자를 설정하지 않은 경우도 같습니다.

관련자에게는 텔레그램으로 **"기한이 지난 요청서를 대리 결재자에게 넘겼습니다"** 또는
**"요청서가 취소되어 기안자에게 반환되었습니다"** 알림이 갑니다.

> 단계 설정 화면에 **"상위 단계로 자동 이관"** 기능은 **없습니다**. 업무상 필요하다면 관리자에게
> 문의하세요 — 5.4장 참고.

## 4. 역할: 인사 — 사람과 계정 관리
<!-- seen-by: hr-admin -->

### 4.1. 직원 목록 조회, 검색, 필터

![인사 화면의 3단계](/docs/img/ko/nhan-su.svg)

1. **인사** 메뉴로 이동합니다: 검색창(이름, 사번, 이메일…)과 **부서** / **계정 상태** 필터가 있는
   직원 목록이 나옵니다.
2. 직원을 눌러 **상세 프로필**을 엽니다: 연락처, 부서 – 주 직위, **겸직** 직위, 시스템 역할,
   그리고 기간별 **직위 이력**.
3. 퇴사한 경우 프로필에서 **계정 잠금**을 누릅니다. 상태가 **비활성**으로 바뀝니다.

> **"직원 삭제"** 기능은 없습니다. 계정은 **잠금**만 되며, 그래서 기존 요청서와 결재 이력이 그대로
> 보존됩니다. 잠긴 계정은 로그인할 수 없지만 과거 보고서에는 계속 표시됩니다.

### 4.2. 직원 계정 생성과 부서 배치

![직원 계정을 만드는 5단계](/docs/img/ko/tao-tai-khoan.svg)

1. **인사** 화면에서 **직원 계정 생성**을 누르면 생성 양식이 열립니다.
2. **성명**, **업무 이메일**(로그인용), **전화번호**를 입력합니다.
3. **부서**와 **주 직위**를 선택합니다 — **이 단계가 직원을 부서에 배치하는 단계입니다.**
   겸직이 있으면 **+ 겸직 직위 추가**를 누르고 어느 것이 **주 직위**인지 표시합니다.
4. **시스템 역할**을 선택합니다. 역할이 메뉴와 권한을 결정합니다. 일반적으로 쓰는 역할은
   **STAFF** · **TEAM_LEADER** · **MANAGER** · **HR** · **ADMIN** 입니다.
   > 목록은 시스템에서 가져오므로 설정에 따라 더 많을 수 있습니다 (이사, 감사, 이사회 등).
5. **저장**하면 시스템이 **임시 비밀번호**와 함께 계정을 만들고 화면에 표시합니다. 직원은 **최초
   로그인 시 반드시 비밀번호를 변경**해야 합니다.

### 4.3. 비밀번호를 잊은 직원의 재설정

![직원 비밀번호 재설정 3단계](/docs/img/ko/dat-lai-mat-khau.svg)

1. **인사** → 직원 프로필을 열고 → **비밀번호 재설정**을 누릅니다 (계정이 활성 상태일 때만 표시되며,
   잠긴 계정은 먼저 잠금을 해제해야 합니다).
2. 시스템이 **임시 비밀번호를 자동 생성**합니다 — 직접 정하지 않습니다. **인사 화면**에 표시되고
   직원의 **텔레그램으로 전송**됩니다(연결한 경우).
3. 직원은 이메일 + 임시 비밀번호로 로그인하고 **즉시 변경이 강제**됩니다 (1.2장).

### 4.4. 부서 & 그룹

![조직도와 부서에 구성원을 추가하는 방법](/docs/img/ko/phong-ban-nhom.svg)

- **부서 & 그룹** 메뉴에서 여러 단계의 **조직도**(위원회 → 부서 → 그룹)와 업무 그룹을 봅니다.
  모든 역할이 볼 수 있습니다.
- 부서를 누르면 구성원, 해당 부서의 요청서, **부서 전용 보고서**를 볼 수 있습니다.
- 구성원 추가: 부서/그룹 카드를 열고 → 구성원 표에서 추가를 누르고 → 직원을 고른 뒤 → 직위별로
  **주 직위 / 겸직**을 설정합니다. **결재 흐름이 쓰는 직속 상사는 바로 이 직위 항목에서 산출됩니다.**
- 부서 이동: **인사** 화면에서 직위를 수정하거나, 그룹에서 삭제한 뒤 새 그룹에 추가합니다.

### 4.5. 보고서와 엑셀 내보내기

![보고서 페이지와 엑셀 내보내기](/docs/img/ko/bao-cao.svg)

1. **보고서** 메뉴로 이동합니다 (인사 / 관리자 권한).
2. 필터 바를 사용합니다: **기간**, **블록**, **부서**, **요청서 유형**, **직위**. 휴대폰에서는
   **필터** 줄을 눌러 펼치거나 접습니다.
3. 블록 구성: 개요 카드, **12개월 추세**(**통합** / **유형별** 전환), 유형·부서별 분포,
   부서 / 직위 비교, 경영 요약 표.
4. 각 표의 **엑셀** 버튼으로 **지금 보고 있는 부분만** 파일로 내보내거나, **보고서 내보내기**로
   범위를 더 세밀하게 지정합니다.
5. 상세 표에서는 **행을 눌러** 개별 요청서를 확인할 수 있습니다.

## 5. 역할: 관리자 — 시스템 설정
<!-- seen-by: hr-admin -->

> 새 요청서 유형을 추가할 때의 올바른 순서:
> **5.1 서식 양식** → **5.2 직위**(없을 때) → **5.3 결재 흐름** → **5.4 기한 초과 설정**
> → **실제 요청서 1건으로 테스트** → 텔레그램 알림 확인.

### 5.1. 서식 양식

![양식을 만들고 입력 항목을 작성하는 3단계](/docs/img/ko/mau-don.svg)

1. **설정 → 서식 양식**으로 이동해 양식을 만듭니다: **이름**, **코드**, **양식 그룹**.
2. 양식 카드의 **연필** 아이콘을 눌러 항목 편집 화면을 엽니다.
3. 항목을 추가합니다: **6가지 입력 유형** 중 하나를 고릅니다 — **텍스트** · **숫자** · **선택**
   (드롭다운 / 라디오 / 체크박스) · **날짜** · **파일 업로드** · **대리 결재자**.
   항목 이름을 정하고 필요하면 **필수**로 표시합니다 (필수 항목은 기안자에게 `*` 로 표시됩니다).
4. **파일 업로드** 유형에서는 직원용 **인쇄 양식 파일**을 첨부할 수 있습니다.
5. **끌어서 순서를 바꾸고** 저장합니다. 새 양식은 **이후 생성되는 요청서에만** 적용되며 기존 요청서는
   내용이 그대로 유지됩니다.

> **결재 흐름이 없는 양식은 사용할 수 없습니다.** 5.3장을 이어서 진행하세요.
>
> **기술 참고:** 화면에서 **항목에 "키"를 지정할 수 없습니다**(키는 자동 생성). 따라서 **휴가 형태**
> 또는 **OT 시간** 기준 조건 분기는 **현재 화면에서 설정할 수 없습니다** — 5.3장 참고.

### 5.2. 직위 & 직급

![결재 기준으로 쓰는 직급 체계와 한 사람의 여러 직위](/docs/img/ko/chuc-vu.svg)

- **설정 → 직위 & 직급**에서 결재 흐름의 **기준**으로 쓸 직위를 등록합니다: 조장, 팀장, 부서장 대리,
  **부서장**, **점장**, 지점장, 지역 관리자, 본부장 등.
- **매장** 블록과 **사무실** 블록은 기준이 다릅니다. 여기서 직위가 틀리면 결재 흐름이 **잘못된 사람**을
  선택합니다 — 실사용 전에 반드시 확인하세요.
- 한 직원이 **여러 직위**를 가질 수 있습니다(주 직위 + 겸직). "직속 상사" 기준 결재 흐름은 직원의
  **주 직위**에서 상사를 가져옵니다.

### 5.3. 요청서 유형별 결재 흐름

![다단계 결재 흐름](/docs/img/ko/luong-duyet.svg)

**설정 → 결재 흐름**으로 이동합니다. **요청서 유형마다 결재 흐름이 따로** 있고, **사무실** 블록 전용,
**매장** 블록 전용, 또는 **양쪽 공통**으로 씁니다. 흐름은 순서대로 나열된 **결재 단계**로 이루어집니다.

1. 상단 선택 상자에서 **서식 양식**을 고릅니다.
2. **다음 결재 단계 추가**를 누르고 그 단계를 설정합니다.
3. **결재 흐름 저장**을 누릅니다.

#### 한 단계의 네 가지 설정 그룹

![한 결재 단계의 네 가지 설정 그룹](/docs/img/ko/luong-duyet-4-nhom.svg)

**(A) 결재 유형 — 이 단계의 결재자.** 네 가지 중 하나를 고릅니다.

| 유형 | 의미 | 쓰는 경우 |
|---|---|---|
| **직속 상사** | 기안자의 직속 상사가 결재 | 부서 표준 흐름 |
| **연속 관리 체인** | 낮은 단계에서 높은 단계로 순서대로 결재 | 여러 관리 단계의 서명이 필요한 요청서 |
| **지정 결재** | 결재 규칙 + 직위 또는 특정 그룹 선택 | 직위 기준으로 맞춤 구성한 흐름 |
| **특정 1명 지정** | 해당 한 사람에게만 전달 | 담당자가 고정된 특수 요청서 |

"직속 상사"에서는 기준을 고릅니다: **직속 상사 / 부서장 대리 / 부서장**.
"연속 관리 체인"에서는 **시작 단계와 끝 단계**를 고릅니다. "지정 결재"에서는 **직위** 또는
**특정 인원 그룹**을 고릅니다.

**(B) 결재자가 여러 명일 때의 규칙** ("지정 결재" 유형에만 적용):

- **순차 결재**: 앞 사람이 결재해야 다음 사람에게 넘어갑니다 (`A ➔ B ➔ C` 로 표시). 순서대로 전원을
  선택해야 하며, 누락이 있으면 시스템이 단계별로 알려줍니다.
- **동시 — 전원 동의 필요**: 모두에게 발송되고 **100%** 결재해야 통과합니다.
- **동시 — 1명만**: **한 명**이 결재하면 즉시 통과합니다.

**(C) 기한 초과 처리** (자세한 내용은 5.4장):

- **기한 내 미결재 시 자동 처리**를 켜고 허용 **시간**을 입력합니다 (기본 12시간).
- **시간 계산 방식**: 주야간 12시간 연속, 또는 **업무 시간만**.
- **처리 방식**: **요청서를 기안자에게 반환** 또는 **기한 초과 위임으로 결재**.

**(D) 단계 순서 & 범위:**

- **끌어서 단계 순서를 바꾸고**, 스위치로 쓰지 않는 단계를 **비활성화**합니다.
- **적용 범위**: 근무지 자동, **사무실** 전용, **매장** 전용, 또는 **공통**.
- **반려 사유 필수**: 이 규칙은 **항상 켜져 있고** 시스템에서 변경할 수 없습니다.

#### 방금 만든 흐름 확인

- **저장**을 누르면 시스템이 설정 오류(예: "순차 결재" 단계인데 결재자를 고르지 않음)를 검사해
  **어느 단계**에 무엇이 빠졌는지 알려줍니다.
- **실제 요청서 1건**으로 테스트합니다: **새 요청서 작성**을 열고 방금 설정한 유형을 골라
  **예상 결재 흐름** 블록을 확인합니다. 설정한 사람/단계가 그대로 나와야 합니다.
- **흐름 수정은 새 요청서에만 영향을 줍니다.** 진행 중인 요청서는 상신 시점의 흐름을 그대로 유지합니다.

> **⚠️ 조건부 단계는 아직 화면에서 설정할 수 없습니다.**
> 시스템에는 **휴가 일수**, **휴가 형태**, **OT 시간**을 `>` `>=` `=` `<=` `<` 로 비교해 특정 단계만
> 실행하는 기능이 **있습니다** (예: 휴가 일수가 3일 초과일 때만 부서장 단계 실행).
> 다만 이 기능은 **현재 앱에 설정 화면이 없고**, 항목에 "키"를 지정할 수도 없습니다(5.1장).
> 사용하려면 개발팀에 API 설정을 요청하세요.

### 5.4. 기한 초과 처리와 대리 결재자

![단계가 기한을 넘겼을 때의 두 가지 경로와 전사 기본 시간 계산 방식](/docs/img/ko/xu-ly-qua-han.svg)

**a) 결재 단계별 기한 초과 설정** — **설정 → 결재 흐름**의 단계 안 **기한 초과 처리** 그룹에서
설정합니다 (5.3장 C). 처리 방식은 **2가지**뿐입니다.

| 처리 방식 | 시스템 동작 |
|---|---|
| **요청서를 기안자에게 반환** | 요청서가 기안자에게 돌아가고 "결재 기한이 지났습니다" 알림을 받습니다. |
| **기한 초과 위임으로 결재** | 해당 단계 결재자가 **위임 → 기한 초과 대리 결재**에서 설정한 **대리 결재자**에게 넘어갑니다 (3.5장). |

대리 결재자도 기한을 넘기거나 결재자가 대리 결재자를 **설정하지 않았다면**, 요청서는 **취소**되어
기안자에게 반환됩니다.

> **참고:** 단계 설정 화면에 **"상위 단계로 자동 이관"** 은 **더 이상 없습니다**. 업무상 상위 결재가
> 필요하다면 기한 초과 처리 대신 흐름에 **결재 단계를 하나 더 추가**하세요.

**b) 전사 기본 시간 계산 방식** — **설정 → 일반 & 텔레그램**의 **기한 초과 12시간 계산 방식** 블록에서
**12시간 연속**(주야간) 또는 **월 → 금 업무 시간만**(주말·공휴일 제외)을 고르고 업무 **시작 / 종료
시간**을 입력합니다. 각 결재 단계에서 이 규칙을 덮어쓸 수 있습니다.

### 5.5. 텔레그램 봇 설정

![설정 화면의 텔레그램 봇 블록과 나머지 두 개의 일반 설정 블록](/docs/img/ko/cau-hinh-he-thong.svg)

1. **설정 → 일반 & 텔레그램**의 **텔레그램 봇 연동** 블록으로 이동합니다.
2. **텔레그램 봇 토큰** 칸에는 현재 토큰이 보안을 위해 점으로 표시됩니다. 변경이 필요하면 텔레그램
   **@BotFather**에서 받은 새 토큰을 붙여 넣습니다.
3. **설정 저장**을 누르면 시스템이 텔레그램에 **봇 토큰을 확인**하고 현재 서버를 가리키는
   **수신 경로(웹훅)를 다시 등록**합니다 — **https 필수**입니다.
4. 카드 모서리의 상태 라벨로 확인합니다: **연결됨**(초록) 또는 **연결 안 됨**. 실패하면 빨간 메시지가
   원인을 알려줍니다: 잘못된 봇 토큰, 텔레그램 접속 불가, 웹훅 주소에 https 누락.

**참고:** 새 봇으로 바꿔도 사용자는 **다시 연결할 필요가 없습니다** — 기존 채팅 연결이 유지됩니다.

> 여기에는 **"테스트 메시지 보내기"** 버튼이 **없습니다**. 알림 채널을 확인하려면 **실제 요청서**를
> 상신하거나(2.1장) **계정** 페이지에서 **텔레그램 연결**을 누르세요 (6장).

## 6. 텔레그램: 연결과 알림 수신
<!-- seen-by: all -->

### 6.1. 최초 연결

![텔레그램 연결과 알림 수신](/docs/img/ko/telegram.svg)

1. **계정** 페이지를 엽니다: 사이드바 **왼쪽 아래의 이름** 또는 프로필 사진을 누릅니다.
2. 알림 벨 줄에 아직 연결되지 않았다면 **텔레그램 연결** 버튼이 표시됩니다. 누르면 회사 봇과 함께
   텔레그램이 열립니다.
3. 텔레그램에서 **Start**를 누르면 봇이 **"연결되었습니다!"** 라고 답하고 연결이 끝납니다.
4. 웹으로 돌아와 **페이지를 새로고침**하면 벨 줄이 초록색 **"텔레그램 연결됨"** 으로 바뀝니다.

**연결 링크 관련:**

- 링크는 **15분** 동안만 유효하고 **1회만** 사용할 수 있습니다. 이전 링크를 다시 누르면
  **"링크가 유효하지 않거나 만료되었습니다"** 가 나옵니다 — 웹으로 돌아가 **텔레그램 연결**을 다시 누르세요.
- **계정** 페이지는 상태를 **자동으로 갱신하지 않습니다** — 텔레그램에서 Start를 누른 뒤 **페이지를
  새로고침**해야 합니다.

### 6.2. 다른 텔레그램 계정으로 변경

**계정** 페이지에서 **텔레그램 연결됨** 옆의 **텔레그램 연결 변경**을 누르고 → 봇 링크를 열어
**새 계정으로 Start**를 누릅니다. **기존 연결은 자동으로 교체됩니다.**

### 6.3. 받게 되는 알림

- 본인 요청서의 **승인** / **반려** / **보완 요청** / **취소**.
- **결재할 새 요청서**, **기한 임박**, **기한 초과 이관** 또는 **취소**.
- 인사가 비밀번호를 재설정할 때의 **임시 비밀번호**.
- **새 댓글** 또는 요청서에서 `@`로 **이름이 언급**된 경우.
- 모든 메시지에 해당 페이지를 여는 **자세히 보기** 링크가 있고, 요청서 이름과 사람 이름은
  **굵게** 표시됩니다.

## 7. 자주 묻는 질문
<!-- seen-by: all -->

**Q: 결재 흐름 도식에 이름 대신 "결재자"라고 나옵니다.**
A: "특정 1명 지정" 흐름이거나 후보가 여러 명인 흐름에서는 시스템 또는 본인이 사람을 정해야 이름이
표시됩니다. **결재자 선택**에서 사람을 고르고 도식을 다시 여세요. 그래도 잘못되면 관리자에게
결재 흐름 설정 확인을 요청하세요 (5.3장).

**Q: 텔레그램 알림이 오지 않습니다.**
A: **계정** 페이지에 **텔레그램 연결됨**이 표시되는지 확인하세요(먼저 새로고침). 아니라면 다시
연결하세요(6.1장). 연결되어 있는데도 알림이 없다면 관리자에게 봇 설정 확인을 요청하세요 (5.5장).

**Q: 사용자가 Start를 눌렀는데 "연결되었습니다!" 가 나오지 않습니다.**
A: **설정 → 일반 & 텔레그램**의 **연결됨** 표시를 확인하고(봇 토큰이 유효한지) **설정 저장**을 눌러
수신 경로를 다시 등록하세요. 또는 15분이 지나 링크가 만료된 경우이니 **계정** 페이지에서
**텔레그램 연결**을 다시 누르세요.

**Q: 결재자에게 기한 임박 알림이 왜 한 번만 가나요?**
A: 스팸 방지를 위한 의도된 동작입니다. 요청서가 **새 결재 단계**로 넘어갈 때만 다시 알림이 갑니다.

**Q: 결재하던 요청서가 대기 목록에서 사라졌습니다.**
A: 기안자가 **취소**했거나, **기한이 지나 다른 사람에게 넘어갔거나**, "1명만 결재" 규칙에 따라
**같은 단계의 다른 결재자가 먼저 처리**했을 수 있습니다.

**Q: 비밀번호를 잊어버렸습니다.**
A: **인사에게 재설정을 요청**하세요 (4.3장). 텔레그램 또는 직접 임시 비밀번호를 받아 로그인하면
**즉시 변경이 강제**됩니다 (1.2장).

**Q: 로그나 데이터베이스의 시간이 화면과 7시간 차이가 납니다.**
A: 시스템은 **UTC로 저장**하고 화면은 **사용자 PC의 현지 시간(GMT+7)으로 표시**합니다. 정상 동작이며
오류가 아닙니다.

**Q: 결재 단계를 하나 더 추가하려면 어디서 하나요?**
A: **설정 → 결재 흐름**에서 해당 서식 양식을 고르고 **다음 결재 단계 추가**를 누른 뒤 새 단계의 결재
유형을 설정합니다 (5.3장).

**Q: 새 요청서 유형을 추가하려면 무엇이 필요한가요?**
A: **서식 양식 + 입력 항목** 생성(5.1장) → 단계가 있는 **결재 흐름** 생성(5.3장) → **실제 요청서
1건으로 테스트** → **텔레그램 알림 확인**(6장).

**Q: 결재 흐름을 수정하면 진행 중인 요청서에 영향이 있나요?**
A: **없습니다.** 요청서는 상신 시점의 흐름을 유지하며, 새 흐름은 이후 생성되는 요청서에만 적용됩니다.

## 부록 C. 시스템에 없는 기능
<!-- seen-by: all -->

아래 버튼을 찾느라 시간을 쓰지 마세요 — 존재하지 않습니다:

- 요청서 작성 창의 **임시 저장** (**취소**와 **요청 상신** 두 버튼만 있습니다).
- 텔레그램 설정 화면의 **테스트 메시지 보내기**.
- **"연결 확인 & 저장"** 버튼 — 실제 버튼 이름은 **설정 저장**입니다.
- **기한 초과 시 상위 단계로 이관** — 화면에는 처리 방식이 2가지뿐입니다 (5.4장).
- 휴가 일수 / 휴가 형태 / OT 시간 기준 **조건부 단계 설정** (5.3장).
- **결재 단계별 대리 결재자** — 본인이 결재하는 모든 요청서에 한 명만 설정합니다.
- **직원 삭제** — **계정 잠금**만 가능합니다.
- **직원 비밀번호 직접 입력** — 시스템이 임시 비밀번호를 생성합니다.
- **"직책"** 화면 — 실제 메뉴는 **설정 → 직위 & 직급**입니다.
- 최상위 **"양식"** 화면 — 실제 경로는 **설정 → 서식 양식**입니다.
